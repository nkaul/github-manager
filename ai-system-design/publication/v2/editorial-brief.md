## Reader and premise

Audience: developers, data scientists and product builders who know GitHub but have not used this app. They should not need prior knowledge of the project's taxonomy, benchmark history or internal state names.

Problem: a repository list exposes names and technologies, while useful organization also depends on purpose, initiative relationships and user decisions. A library and an application can share a framework without belonging to the same project. Repeated organization must also distinguish new work from completed analysis and deliberate re-analysis.

Product: GitHub Manager connects a GitHub account, discovers accessible repositories and helps the user review a vocabulary and repository relationships. The implementation in this case study is local Next.js/FastAPI/SQLite. Hosted inference is restricted to approved public/synthetic evidence.

Reader payoff: follow the two AI phases with inspectable data, understand how context/retrieval/state/budget choices serve the product, and identify experiments worth doing next.

Central argument: an AI organizer becomes useful when its evidence, vocabulary, user authority and processing history remain coherent across decisions. Model generation is one stage in that workflow.
