# Illustrated Explainers

Make the mechanism understandable through recognizable objects, readable evidence and visible consequences. Use the illustrated paper-and-marker language in the bundled references; adapt the subject and facts to the current task.

## Route by deliverable

- For a still illustration, read [style and composition](references/style-and-composition.md). Inspect a relevant image in `assets/` or the user's supplied reference before generating.
- For accurate labels, complex technical content or revision, read [content and visual QA](references/content-and-qa.md).
- For diagram-style video, also read [motion and narration](references/motion-and-narration.md).
- For reusable generation/edit instructions, use [prompt patterns](references/prompt-patterns.md).
- Source history and the purpose of bundled images are in [provenance](references/provenance.md); they are not current facts about another project.

Load only the detail needed for the requested work. A narrow label correction does not require a new article, animation or complete diagram redesign.

## Working contract

1. Establish the viewer's question and the explanation's purpose before choosing objects. Identify the input, operation, result and practical consequence; make a comparison or exception visible when it changes the conclusion.
2. Separate the **content contract** from the style reference. Inventory required labels, relationships, figures, scope and qualifications. Preserve implemented, historical, illustrative and proposed status. An old architecture drawing is not evidence that its components are deployed.
3. Draw meaningful objects: repository documents, highlighted source passages, a magnifying glass, a policy sieve, a request booklet, a robot returning structured data, a person reviewing it, a receipt retained after labels change. Let the subject determine the metaphor. Use panels as light framing, not a substitute for illustrating the mechanism.
4. Build a clear reading path with generous whitespace. Favor blue and indigo headings, occasional purple emphasis, dark ink and soft lavender/light-blue washes. Use yellow/green sparingly for meaning. Restate tiny reference-image text at a readable size; do not expect a dense raster image to become legible through enlargement alone.
5. Use an available image-generation/editing tool for new raster artwork. Inspect existing images before editing; preserve originals and supply actual style references using the tool's supported reference mechanism. For existing SVG/code-native diagrams, exact text overlays or independently moving elements, prefer native vector/HTML/SVG editing. Follow the chosen tool's own instructions.
6. Verify the actual export: wording, numbers, units, arrow semantics, status, contrast, margins and reading order. Compare it against the content inventory and inspect at the intended display size. Fix specific errors without dropping facts or changing unrelated areas.
7. Deliver the figure with a useful caption, alt text and source/status notes where needed. For a series, preserve visual continuity while using a composition suited to each explanation. If density defeats readability, split the explanation into linked figures or stages and retain its full coverage.

Do not invent schema fields, source coordinates, measurements, features or hidden model reasoning to decorate the scene. Do not imply that two independent facets form a hierarchy because an arrow looks tidy. A reference can provide visual language without supplying the new diagram's technical content.

Keep previous academic diagrams and illustrated editions when the user requests preservation. Creating local figures or publication copy does not itself authorize uploading or publishing them. Existing session authorization still governs; do not ask again for a routine revision already within scope.
