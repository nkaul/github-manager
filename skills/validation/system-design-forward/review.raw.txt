# Research Shelf: architecture review and local implementation plan

Review date: October 16, 2026. Status: planning only. The supplied prototype does not yet demonstrate the approved behavior of a usable local organizer with reviewed categories. The immediate work is to protect researcher decisions, enforce the public/private model boundary, and make analysis and budget state durable before adding more automation. Cloud workers and a vector database remain deferred.

## Representative workflow and required invariants

A researcher imports a public paper, sees its abstract, requests organization against approved categories, reviews a suggestion and accepts or rejects it. The accepted decision becomes browseable and searchable locally. Running organization again should recognize the completed analysis even when the researcher leaves the paper without a folder or rejects all suggested categories.

Proposed path:

```mermaid
flowchart LR
    A[Connector facts and visibility] --> B[Local paper record and source version]
    B --> C{Access, privacy, freshness and budget admission}
    C -->|eligible public content| D[Bounded classification request]
    C -->|private or otherwise excluded| E[Explain skip; allow manual organization]
    D --> F[Validate IDs, evidence and result schema]
    F --> G[Pending suggestion and durable analysis receipt]
    G --> H[Researcher accepts or rejects]
    H --> I[Local categories, folders and search]
```

The diagram is a proposal. No component was created or exercised during this review.

The design must retain these invariants:

- Connector refresh changes source facts, not researcher-owned accepted memberships or rejection decisions. Record paper identity in the connector namespace and a source version/content hash; whether the supplied `id` already has this stability is unknown.
- Private or unknown-visibility abstracts are excluded at the final outbound model boundary. An authenticated connector is permission to read within its scope, not permission to export every abstract to a model.
- Model output creates a proposal, not an accepted decision. Unknown/retired category IDs, malformed output and invalid evidence do not become memberships. Source text is untrusted data even when it resembles instructions.
- Successful, validated `NO_MATCH` is a completed analysis. Analysis completion, accepted category coverage, folder membership, freshness and pending review are separate states.
- Repeated requests reuse the durable receipt when the relevant inputs and approved category version are unchanged. Explicit re-analysis records the reason, exact cohort and fresh allowance checks; deleting organization history does not implicitly authorize it.
- A category edit, manual correction, rejection, access change or reset during a running request prevents stale results from overwriting the newer state. Retain the attempt and cost evidence even if its suggestion is discarded.
- Every actual external HTTP attempt consumes an allowance unit, including retries and provider count requests. A window renewal never erases cumulative cost, receipts or previous decisions. Ambiguous provider outcomes retain a conservative cost hold until resolved.

## Proposed local design and choices

Keep one local Python service and SQLite. Separate logical records rather than introducing independent services: source papers/visibility, approved category definitions, pending suggestions, researcher decisions, analysis receipts, runs, allowance windows, HTTP attempts and cost reservations/settlements. The supplied fixture does not establish their schema; migrations and preservation checks are proposed work.

Keep folder semantics intact until their actual cardinality is inspected. Proposed categories are independent reviewed concepts with stable IDs and paper memberships; do not import GitHub Manager's Domain/Project hierarchy into Research Shelf. For the initial slice, allow existing-folder navigation plus approved-category filtering. Whether categories should be mutually exclusive, hierarchical or many-to-many is a material product choice to confirm with the implementation plan; a conservative default is independent many-to-many categories with no new hierarchy. Explicit manual decisions take precedence over automatic proposals.

Use a single local execution path initially. A transaction admits a run, captures source/category revisions and reserves its finite budget; the network request occurs outside the database transaction; a second transaction settles usage, stores the receipt and conditionally applies a pending suggestion only if its revisions remain valid. Do not hold a database write lock across a remote call. Record abandoned/uncertain attempts after a process interruption; avoid automatic paid retries when the prior outcome is unknown. A database admission guard is still needed even with one worker because repeated starts and restarts exist.

Use local text search as the first retrieval baseline. A full abstract plus a small reviewed category registry may fit a bounded classification request without a separate retrieval service. If the registry or text volume outgrows the request budget, first compare deterministic lexical category selection and section/passage packing against the full-registry baseline. Evaluate synonym/no-match failures before proposing embeddings or hybrid retrieval. A vector database is neither present nor required by the supplied evidence. No deployed RAG, reranker, agentic loop or memory system is demonstrated.

Two assumptions need to be made explicit at approval: what “20 HTTP attempts” covers, and category cardinality. Until clarified, budget design should conservatively count all external connector/provider attempts under the granted window, identify the channel in each ledger entry, and keep model dollars separately capped at $3. Twenty model function invocations are not proof of twenty actual HTTP requests. A window limit change means a total allowance unless the UI explicitly says additional attempts; renewing a window is separate from spending authorization. The chosen model, pricing, output bound and whether provider token-count calls are used remain unresolved; no old project defaults should be copied.

Cloud deployment, a managed vector store, autonomous background organization and automatic acceptance are outside the local completion gate. Revisit a queue only when measured local run duration/concurrency or recoverability requires it. Revisit dense/hybrid retrieval only after a realistic, independently reviewed evaluation shows material failures of the lexical/full-registry baseline. Neither revisit authorizes implementing a superseded historical proposal.

## Evaluation and readiness gate

For category quality, use a small researcher-reviewed paper set with allowed labels, explicit no-match/ambiguous cases and immutable abstract versions. Keep study/development examples separate from a locked evaluation subset and group duplicate paper versions together. Measure per-category precision/recall and review acceptance/rejection on the actual evaluated subset; validate category ID correctness and evidence support separately. For candidate retrieval, if introduced, measure whether the approved reference categories survive its cutoff before grading final generation. There is no basis here for a numerical accuracy claim, a model recommendation or a named RAG-framework integration.

For harness correctness, verify the exact boundaries in the phase table with controlled scenarios and captured outbound calls rather than implementation-mirroring assertions. For usability, record a researcher completing the import → review → correct → find → restart → repeat workflow. Connector authentication success, a successful model probe and passing mock tests are distinct evidence; none alone proves full readiness.

This review did not execute the prototype, install packages, authenticate, invoke models, inspect a real SQLite database or mutate the application. Only this planning artifact was written. The four fixtures are deliberately reduced, so absent behavior is described as not demonstrated except for the directly visible unsafe paths. Implementation remains gated on approval of the concrete plan; factual readiness and cost/quality results must be collected later.
