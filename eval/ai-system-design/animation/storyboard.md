# GitHub Manager — two-minute pilot storyboard

Status: approved for the short pilot on October 15, 2026. Full companion awaits feedback.

The scenes use existing illustration artwork with code-native moving cards, drawn paths, highlights and state changes. All times follow the generated narration.

## 00.00–16.60 · Your repositories deserve a map.

Your own repositories. Shared projects. Libraries you starred for later. Finding them is easy. Remembering how they fit together is harder. GitHub Manager brings them into one workspace, where you can search, explore, and organize.

Visible cues: Shared projects at 3.04s; GitHub Manager at 10.94s; search at 13.94s.

## 16.60–30.43 · Same technology. Different purpose.

Projects group an initiative. Domains group those projects. Topics describe capabilities, and tags describe technologies. Two repositories can both use Python without belonging to the same project.

Visible cues: Domains at 19.68s; Topics at 21.62s; Two repositories at 26.04s.

## 30.43–45.47 · Agree on the vocabulary first.

There are two separate AI jobs. Taxonomy discovery proposes a vocabulary from a collection of repositories. You review and edit it. Classification then works with approved concepts, rather than inventing new labels.

Visible cues: proposes at 34.68s; You review at 38.40s; Classification at 40.16s.

## 45.47–61.50 · Keep the sentence that explains why.

Follow our synthetic Orion example. Its README says: patient intake API for the Orion Clinical Platform. Uses FastAPI and Python. We keep that purpose sentence, its evidence reference, and useful phrases.

Visible cues: patient intake at 50.18s; Uses FastAPI at 53.40s; purpose sentence at 57.30s.

## 61.50–74.16 · A shortlist is not a decision.

Local search retrieves six possible concepts. Some are distractions: Forge shares the word platform, but that doesn't establish a relationship. Retrieval finds possibilities. It doesn't assign them.

Visible cues: six at 63.03s; Forge at 66.45s; doesn't assign at 72.69s.

## 74.16–91.70 · Show the model evidence and boundaries.

The model receives evidence, candidate definitions, instructions, and a response schema. In the saved test, it selected Orion, Web APIs, FastAPI, and Python, citing the purpose sentence. You review those suggestions before accepting them.

Visible cues: response schema at 78.65s; selected Orion at 81.45s; citing at 86.85s; You review at 88.27s.

## 91.70–104.30 · Remember the work. Respect your decisions.

The app remembers completed analysis separately from labels. Removing a project doesn't erase that receipt. Later changes can reconcile locally. A fresh AI analysis remains an explicit choice.

Visible cues: Removing at 96.04s; reconcile locally at 99.44s; explicit choice at 102.82s.

## 104.30–120.00 · Useful organization. Your control.

Every model call has a reviewed budget: count, reserve, generate, record. Find the repository you need. Understand why it belongs. Keep the final decision yours.

Visible cues: count at 108.69s; Find the repository at 112.85s; yours at 118.51s.

The Orion example is authored synthetic input with a saved real API result. Taxonomy discovery is explained conceptually; its saved draft and the classification benchmark used separate registries. The removal of a Project is an illustrative user action. No new repository inference was performed.
