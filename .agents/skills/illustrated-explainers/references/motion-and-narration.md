# Diagram-style motion and narration

Use this reference when the deliverable is an animation. A flattened illustration is a visual source, not an articulated character rig. Use browser viewports to focus it, or draw separate native vector layers for independently moving words, documents, chips and arrows. Preserve source pixels unless an edit is requested.

## Turn prose into visible events

For each substantive passage, identify the viewer's question, starting state, visible operation, resulting state and consequence. Then tie the event to a narration cue and its evidence. Examples:

| Explanation | Useful motion |
|---|---|
| Similar technology does not establish initiative membership | Align two technology chips, then connect only the source-supported repository to the initiative |
| Evidence selection can lose context | Reveal source paragraphs, retain purpose/negation and visibly exclude irrelevant installation material |
| Retrieval supplies possibilities | Highlight matching terms and populate a shortlist; do not turn scores into membership probabilities |
| Augmentation has inspectable contents | Evidence, candidate definitions and policy/schema cards assemble into a request booklet |
| Generation is a bounded proposal | Reveal actual returned IDs and their source references, leaving distractors unselected |
| A user correction persists | Remove an association while retaining its processing receipt and rejection state |
| A spending bound prevents dispatch | Transfer a reserved amount, show settlement/unknown hold, and stop before the next inadmissible call |
| A good aggregate score can hide a failure | Separate retrieval, evidence support, classification and workflow result trays |

Use motion to communicate a causal change, not only to pan across paragraphs. Keep the result still long enough to inspect. Avoid perpetual motion around reading text.

## Orient and pace

Announce each section by name, introduce its purpose and show how it connects to the preceding step. Keep a visible section label/purpose or a small progress ribbon when it helps a longer explanation. Do not jump straight into acronyms or a new mechanism.

Measure actual speech rather than trusting a speed setting. In this project, the roughly 126 spoken-word/minute pilot felt fast; the revised educational companion averaged about 108 with longer holds. Those are dated user-feedback examples, not universal voice-speed requirements. Choose a pace appropriate to the audience and terminology; let runtime follow the explanation. Offer chapters instead of compressing all insights into a fixed short film.

Keep voice and directions consistent across coherent takes. Include purposeful pauses after introductions and results. Synchronize captions and visual events to measured narration; inspect source-level and encoded transitions. Recognized omissions need repair or explicit disclosure, not invented timestamps. Avoid speech time stretching merely to hit a duration.

## Technical handoff

For reproducible native animation, an explicit `seek(time)` scene renderer and cached scene chunks can make revisions local. Render at the requested delivery size/frame rate; 1920×1080/30fps was used for the illustrated companion. Match the current task rather than forcing that format on every deliverable.

Package a poster, transcript, captions and navigable chapters when the scope calls for them. Native caption placement and player controls can obscure art; inspect the real player in normal/full-screen and smaller layouts. A separate caption area is often useful.

Validate media decode, frame count, dimensions, duration, audio levels, caption order, chapter seeks, representative encoded motion and source preservation. A typical speech-led loudness target is around −16 LUFS with peaks below −1 dBTP, subject to the publishing destination. Record real measurements and distinguish muted playback automation from listening judgments.

Use finite, already authorized media budgets and request counts, cache successful takes, and retain uncertain spending bounds. Media calls and application inference are different ledgers unless the task explicitly shares them. Local media production does not imply publication permission.
